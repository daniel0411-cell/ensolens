# Production redesign audit

Observed October 22, 2026 (Asia/Shanghai). Audited local commit f97040c and https://ensolens.com/ without changing application code or deploying. The supplied screenshot was treated as a claim to verify.

## Findings

1. **P2: Small data labels fail normal-text contrast requirements.** `src/styles/global.css:16` defines `--subtle: #64748b`; `.stat-label` uses it at 11px (`:224`). Contrast is approximately 3.82:1 against the status panel after compositing its 75% background over #090e0c, below WCAG AA's 4.5:1 normal-text threshold. Figure notes and other metadata also use this token. Increase metadata contrast and check every actual background. This affects reading the meaning and dates of the otherwise prominent numbers.

2. **P2: Expanding the map makes it smaller on mobile.** At a 390 x 844 viewport the image measures 305px wide before opening and 272px afterward. `src/styles/global.css:854` adds 24px dialog padding, while the moved map retains its own padding (`:365`). The button still says “Expand ocean map”, but observation dates and the source scale become harder to inspect. Reduce mobile dialog/map padding or offer an original-resolution zoomable view; the expanded image should be at least as large as the inline image. Modal open, close and Escape do work.

3. **P2: The homepage overflows horizontally at 320px.** Observed document scroll width 329px at innerWidth 320px. The `Data notes` link in `.provenance-line` reaches x=328.9; the strip keeps its nonwrapping outer items, gap, and single-row flex layout (`src/styles/global.css:692`). Add a mobile wrapping or stacked layout with shrinkable children. The 390px page does not reproduce this failure, explaining why the existing width-only overflow check misses it. The audit also inspected 820px, 900px and 1440px layouts.

4. **P3: The phase badge crosses the status-column separator near the tablet breakpoint.** At 820px, the first column ends at x=271.2 but the badge ends at x=282.0. `.phase-value` stays nowrap and the status band keeps four columns until 800px (`src/styles/global.css:887`). The label intrudes into the neighboring cell. Switch to two columns earlier or wrap the phase and alert within the cell. Whole-document overflow assertions do not detect this internal overlap.

5. **P3: Sticky navigation covers the methodology anchor label.** On https://ensolens.com/methodology/#indices at 390px, the sticky header ends at y=65; the section eyebrow starts at y=54.9 and is obscured. `.method-section` retains only a 20px scroll margin (`src/styles/global.css:832`) despite the newly sticky header (`:66`). Account for header height in anchor offsets at both desktop and mobile widths.

6. **P3: Recovery documents disagree about the current production version.** At audit start, README.md:11 names 961bd7ff, PROGRESS.md:30 names 1b2be18d, and the latest PROGRESS section names ef995825. Only the last matches the actual current deployment. This can mislead subsequent troubleshooting and rollback choices. Preserve older releases as dated history and keep one clear current production record.

## Additional retained concerns and limits

- The inherited anomaly strip is labeled -2 to +2 degrees while the displayed weekly value is +3.3 and the marker is clamped to 96% (`src/pages/index.astro:27`). Consider an explicit out-of-range indicator or a dynamic scale. This predates the redesign commit.
- Mobile data cards occupy most of the first screen, and the bottom provenance copy becomes a narrow column even at 390px. These are design-density concerns beyond the reproducible overflow finding.
- Existing browser tests check canvas pixels, document overflow at 1440/390, and modal open state. They do not check contrast, relative expanded image size, internal overlap, or anchor occlusion. Passing them does not resolve these findings.
- The full local Worker scheduled-refresh/browser release gate was not rerun, because no release or runtime change was made. Historical compliance with the release gate cannot be established from current passing checks alone. Performance profiling, screen-reader coverage, security penetration testing and current source-by-source NOAA editorial verification are outside this focused redesign audit.

## Recommended order

Fix metadata contrast, mobile map sizing and narrow-screen overflow first. Then adjust the tablet status layout and anchor offsets, and reconcile the release documentation. Preserve the current deployment until a scoped follow-up passes the project's release gate.
